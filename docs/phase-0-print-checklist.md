# المرحلة 0 — قائمة التحقق اليدوي من الطباعة

الاختبارات الآلية بتتأكد إن أوامر TSPL سليمة ومش بتتغير. لكن الحكم النهائي على الليبل هو **الطابعة الحقيقية والماسح**. القائمة دي تتعمل مرة دلوقتي (مرجع)، وبعد كل مرحلة بتلمس الطباعة.

## المطلوب
- طابعة Xprinter TSPL المستخدمة في وسيلة، ببكرة ليبل 75×130mm.
- موبايل Android عليه التطبيق.
- ماسح باركود يدوي + كاميرا موبايل (تطبيق ماسح أو Odoo Barcode).

## 1. ليبل مرجعي (قبل التعديلات)
1. نزّل نسخة من commit `c0649f9` (قبل المرحلة 0) واطبع المنتجات الثلاثة دي:
   - منتج **بدون متغيرات**، الباركود Code128 (حروف وأرقام).
   - منتج **بمتغيرات** (اسم متغير عربي)، الباركود EAN-13 لو موجود.
   - منتج بباركود **طويل** (أطول باركود عندكم).
2. علّم الليبلات واحتفظ بيها.

## 2. ليبل بعد المرحلة 0
1. نزّل النسخة الجديدة واطبع نفس المنتجات الثلاثة.
2. قارن جنب بعض: اللوجو، الاسم، المتغير، الباركود، الأرقام تحته، "Made in Egypt". **المفروض يكونوا متطابقين** (التغيير الوحيد إن الخطوط بقت جوه التطبيق بدل ما تتحمّل من النت).
3. امسح كل باركود بالماسح اليدوي وبالكاميرا، وسجّل النتيجة في الجدول.

## 3. طباعة بدون إنترنت (جديد في المرحلة 0)
1. امسح بيانات التطبيق أو ثبّته من جديد، وسجّل الدخول وافتح منتج.
2. اقفل الإنترنت (وضع الطيران + شغّل البلوتوث بس).
3. اطبع ليبل. **المفروض الطباعة تشتغل والعربي يظهر صح.** قبل كده، أول طباعة كانت محتاجة نت عشان الخطوط.

## 4. تسجيل hash الليبل على Android (مرة واحدة)
وصّل الموبايل المرجعي بالكمبيوتر وشغّل:

```bash
flutter test integration_test -d <device-id>
```

انسخ سطور `LABEL_HASH android ...` من المخرجات إلى `_goldens['android']` في `integration_test/label_snapshot_test.dart`، واعمل commit. بعد كده أي تغيير في بايتات الليبل على الموبايل ده هيظهر كفشل في الاختبار.

## ملاحظة معروفة
الـ BITMAP بتاع الباركود بيتبعت ومعاه `\r\n` زيادة بعد الـ header (`lib/core/utils/tspl_label_builder.dart`، أمر الباركود). الطابعة بتقرا البايتين دول كجزء من الصورة، فالباركود بيتزحزح تقريبًا 16 dot (~2mm) لليمين عن نص الليبل. ده سلوك **موجود من قبل المرحلة 0** والاختبار الآلي بيرصده. إصلاحه مخطط مع محرك الليبل الجديد (المرحلة 5)، أو قبل كده لو حبيت.
